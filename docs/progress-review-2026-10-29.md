## 30 秒快速回顧

這是一套在 Windows 本機離線運作的 Flask + SQLite 條碼報工系統。主要用途是建立產品製號批次、列印 START／FINISH 條碼、使用 USB 掃描器進行整批開始與完成報工，最後從報表查詢或匯出 Excel。

目前主要報工流程、五軸組裝階段、管理功能、資料保護及 Windows EXE 打包準備已完成。現在正在進行「組裝人員報表統計」，相關程式已寫完且通過 37 項自動測試，但尚未提交到 Git。

## 使用者實際操作流程

1. 先在「機型主檔」建立機型及製號字首。
2. 在「組裝人員」建立可選擇的員工。
3. 建立報工批次時，選擇機型、組裝人員、製作年份，並輸入起始流水號與台數。
4. 系統連續產生每台產品的製號，並列印一張 60×60 mm 批次標籤。
5. 開始工作時掃一次 START，整批內每台產品同步變成進行中。
6. 全批完成後掃一次 FINISH，整批內每台產品同步完成。
7. 從「報表與匯出」按日期、機型、製號、狀態或組裝人員查詢。

## 已完成的功能

### 1. 產品製號與批次

- 依機型字首、製作年份及流水號自動產生製號。
- 製作年份加 1 後取兩位數作為年號；例如 2026 年的 HR-255 第 10 台為 `E27-10`。
- 批次建立時手動輸入起始號與台數，系統自動連號。
- 已使用的製號會被阻擋，不會重複建立。
- 每個產品製號都有一筆報工明細，但同批只使用一張 START／FINISH 標籤。

### 2. 條碼與掃描報工

- 產生短 Code128 條碼，主要資料保存在 SQLite。
- 支援 USB HID 掃描器以 Enter 送出條碼。
- 防止重複 START、重複 FINISH 及未 START 就 FINISH。
- 掃描紀錄會保存結果、時間與操作人。
- 畫面、列印預覽與 Excel 時間統一顯示為台灣時間。

### 3. 五軸組裝流程

- 機型名稱以 `F` 開頭時，建立批次必須選擇旋轉軸、傾斜軸、尾座或組合。
- 同一個五軸製號可分別建立不同組裝階段。
- 同製號、同階段不可重複。
- 條碼包含階段識別，掃描到錯誤階段時會拒絕處理。
- 報表及 Excel 都會顯示組裝階段。

### 4. 主檔與管理功能

- 機型主檔：機型名稱、製號字首、說明、啟用／停用。
- 組裝人員主檔：新增、停用、重新啟用。
- 最近批次：查看最近 20 批並重新列印原標籤。
- 錯誤批次可刪除，但會先建立及驗證資料庫備份。
- 未被使用的機型可刪除；已有關聯資料的機型只能停用。
- 舊機台主檔與歷史 snapshot 繼續保留，但不參與新產品流程。

### 5. 密碼與資料保護

- 最近批次、報表、機型、組裝人員、設定及清除資料等功能有密碼保護。
- 密碼以 Werkzeug hash 儲存，不保存明文。
- 設定頁可變更密碼，也可暫時關閉功能密碼以便排查。
- 備份、批次刪除、清除除錯資料及還原都有基本保護與稽核紀錄。
- `instance/intjr.db` 及 `instance/backups/` 不會提交至 Git。

### 6. Windows EXE 打包準備

- `config.py` 已支援打包後以 EXE 所在資料夾為基準。
- SQLite 資料庫會位於 EXE 外部可寫入的 `instance` 資料夾。
- EXE 啟動 Flask 後會自動開啟瀏覽器。
- 已建立 `build_exe.ps1`，預設使用 PyInstaller `--onedir` 建置。
- 尚需在乾淨的 Windows 環境完整實測打包結果。

## 重要業務規則

- 新產品製號不是舊機台編號。
- 新報工不需要先建立機台主檔。
- 一個批次有多筆產品明細，但整批只掃一次 START 與一次 FINISH。
- 不在 FINISH 時另外輸入完成數量。
- 舊工單號、產品批號、製程、計畫數量與歷史 snapshot 必須保留，不可直接刪除或重新解讀。
- 資料庫時間以 UTC 儲存，使用者畫面轉為台灣時間。
- 任何 schema 變更必須附帶 migration 與回歸測試。
- 不可清除、還原、覆蓋或提交本機 `instance/intjr.db`。
