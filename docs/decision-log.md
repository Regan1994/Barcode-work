# 業務決策紀錄

## 已確認：產品製號與批次報工（2026-10-16）

使用者確認：

- 產品資訊包含機型型號與製號；一個製號只對應一個產品。
- 機型與製號字首對應：HR-255＝E、AR-210＝C、AR-170＝B、RC-210＝CR、RC-255＝ER。
- 製號年號為製作年份加 1。例如 2026 年製作的 HR-255 第 10 台為 `E27-10`。
- 每年流水號從 01 起算，但既有歷史產量難以計算，所以每次建立批次由操作員手動輸入起始流水號和台數；系統依序連號。若起號為 E27-10、台數 10，範圍為 E27-10 到 E27-19。
- 批次內每個製號各存一筆產品報工；同批只刷一次 START，等全部產品完成後刷一次 FINISH。
- 移除新流程中的工單號、產品批號、製程、計畫數量欄位。台數是批次建立時的產品數，不是 FINISH 時另填的完成數量。
- 新產品製號不是舊機台編號；舊機台主檔與歷史報工仍保留，不重新解讀、不覆寫歷史 snapshot。

## 已確認：機型製號字首

機型主檔儲存 `serial_prefix`。已確認的五種機型會由資料庫遷移自動填入字首；其他機型由管理者在機型主檔填字首。

## 組裝人員（2026-10-19）

- 新建報工需從啟用中的組裝人員清單選取人員，不再自由輸入姓名。
- 組裝人員可新增、停用及重新啟用；停用不刪除既有報工紀錄。
- schema migration v4 新增組裝人員主檔；歷史 `operator_name` 欄位保留，介面及報表稱為「組裝人員」。

## 新產品不預先維護機台主檔（2026-10-19）

- 新產品報工不需要先建立或選擇機台主檔；現場不需維護上百台機台清單。
- 建立報工時選擇機型、輸入製作年份、起始流水號與台數，系統直接產生產品製號與每台產品的報工明細。
- 例如 HR-255 的製號字首為 E，2026 年建立 10 台且起始流水號為 1 時，產生 `E27-01`～`E27-10`；下一批從 11 開始產生 `E27-11` 起。
- 舊 `machine_master`、舊機台編號與歷史 snapshot 保留，不刪除、不重新解讀；它們不參與新產品流程。

## 首頁、報表與 Excel（2026-10-19）

- 首頁直接提供 USB HID 條碼掃描輸入；舊 `/scan` 連結導回首頁。
- 首頁「已取消」狀態卡片保留顯示，但不提供點擊或取消操作。
- 報表不提供批次篩選或批次欄位。
- Excel 只匯出一張明細表，欄位固定為機型、製號、狀態、開始時間、結束時間、時長、組裝人員。

## 實作與資料保護

- 新資料庫 schema migration 版本 3 允許產品報工不關聯機台，並加入 `product_serial`、`manufacturing_year` 與唯一製號索引。
- schema migration 版本 4 新增組裝人員主檔。
- schema migration 版本 5 允許新產品報工不填寫舊機台 snapshot；既有歷史 snapshot 保持原值。
- 歷史機台編號、工單、數量、狀態及 snapshot 不做回填或刪除。
- 新產品批次固定共用 START／FINISH；歷史逐筆條碼仍可按舊設定讀取。
- 2026-10-16 自動化回歸測試：16 passed；現場印表機與掃描器測試待執行。
