## 最新想法：打包成 Windows EXE

使用者希望之後能把系統輸出到其他電腦使用。這項工作目前只有規劃，尚未開始實作。

建議先做「資料夾版可攜式程式」，不要一開始做單一檔案：

```text
INTJR\
├── INTJR.exe
├── templates\
├── static\
└── instance\
    ├── intjr.db
    └── backups\
```

建議採用 PyInstaller `--onedir`，原因是：

- 不需要其他電腦安裝 Python。
- `templates`、`static` 及 Flask 程式可一起打包。
- SQLite 資料庫留在 EXE 外部，更新程式時不會覆蓋現場資料。
- 比 `--onefile` 容易處理資料路徑、備份與防毒誤判。

### EXE 工作待辦

1. 新增 PyInstaller 設定檔，納入 `templates` 與 `static`。
2. 讓資料庫固定使用 EXE 同層的 `instance`，或明確支援 `INTJR_DATA_DIR`。
3. 新增建置腳本，例如 `build_exe.ps1`。
4. 新增啟動腳本，啟動 Flask 後開啟瀏覽器。
5. 以乾淨的 Windows 資料夾測試，不依賴開發機的 Python 或套件。
6. 測試掃描器、標籤列印、Excel 匯出、備份與資料庫 migration。
7. 完成後建立 `dist/INTJR/` 測試版，再決定是否要做安裝程式。

### EXE 工作限制

- 不要把 `instance/intjr.db` 放進 Git 或打包檔的唯讀資源區。
- 不要清除、還原或覆蓋目前本機資料庫。
- 不要在尚未確認資料路徑前直接做 `--onefile`。
- 打包後仍維持 `127.0.0.1:5000` 本機模式，除非使用者另外要求區網共用。
